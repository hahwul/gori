# Changelog

## Unreleased

- TUI: the Fuzzer's `^N` line no longer tells you to type into a field that is in READ. `load_blank` opens the TARGET in READ mode, so the toast's “type the target URL” named a gesture that edited nothing — and because the field holds a URL, its digits fired the global 1-9 tab jump and walked the operator off the session they had just made. It names `i/↵` now, the way `repeater_new` already said “edit” (#912).
- TUI: a confirmation that cannot be drawn can no longer be committed. `ConfirmDialog` demanded its full height and drew NOTHING below it while `handle_key` went on answering, so on an 80×12 terminal `⇧X Clear history` armed a modal that showed no heading, no count and no “This can't be undone” — and `y` still deleted every flow in the project. The card now degrades instead, keeping its heading and buttons down to four rows and clipping the message with an ellipsis, and below that it refuses `y`/↵ and stays up so a resize can rescue it (`n`/esc still cancel, because cancelling an unreadable confirm costs a keystroke and committing one costs the data). This is the rule ProjectPicker already applied at its own open site, moved to where a resize after arming can also reach it, and it covers every confirm the Runner raises (#912).
- TUI: three lists stopped painting outside themselves on a small terminal. History's STA cell is the one column in its right-anchored cluster that was not gated on spare room, so at 40 columns with a `strip` colour rule armed it drew from the fixed `host_x` straight over the frame's hairline — `2┃0` on every row, the scroll gauge painted through the middle of a 200. The OAST CALLBACKS table drew its header labels with no width at all and floored the row's DESTINATION cell at six columns whatever was left, so the right-anchored PROVIDER started left of the fixed runs and the three overwrote each other (`PROVIDERTINATION` at 70 columns, the provider eating the source IP and the header leaving the card at 52). And the Notes link preview, carved off the editor's last row, landed on the filter bar above it when there was no row to spend (`/linkser[repeater] XSS PoC (+2)`) (#912).
- MCP: `send_request` refuses a stored source (`flow_id`/`repeater_id`) passed together with `url`/`method`/`headers`/`body`/`raw`/`h2_fields` instead of replaying the stored request and naming the dropped overrides afterwards, so an unintended resend can no longer happen before the warning arrives; `mine_start` and `sequence_start` likewise refuse two template sources. `verbatim` now reaches a `repeater_id` replay, matching `gori run repeater send --verbatim` (#906).
- Fuzzer: **Auto Content-Length now means what it means in the Repeater** — it ADDS the header to a template that carries a body and declares no length, instead of only recomputing one that is already there. The knob had only ever rewritten a declared header, so a request with a body and no `Content-Length` went out with the body on the wire and nothing framing it, and an HTTP/1.1 origin read a **zero-length body**: a request body has no close-delimited form, so `Connection: close` cannot delimit one. Every payload of the sweep was then scored against a request the origin never read a body from, under statuses that looked like a clean run. The same request replayed one tab over worked, because the Repeater's `^L` has added the header for as long as it has existed (`FlowRequest.resync_content_length`, `add_if_missing: true`) — which is exactly what kept this invisible: a template seeded from a repeater session, or hand-authored without the header, behaved differently in the two tabs that share it. Turning it off is still spelled by turning that same switch off (`--verbatim`, MCP `update_content_length: false`, the ADVANCED card's **Auto Content-Length**), because a length that disagrees with the body — or no length at all — is a real desync test. **And when the switch leaves a body unframed, gori says so before the first send** rather than letting the run go quiet: `Plan#unframed_body?` reports a body carrying neither `Content-Length` nor a chunked `Transfer-Encoding` that nothing will frame, as a CLI warning naming the flag and on the Fuzzer tab's run-start line, where it retracts itself the moment the template is edited to declare one. It is a note and not a refusal, for the reason `ws_ignored_knobs` is: an unframed request is a legitimate thing to send on purpose — what is not legitimate is sending one by accident and being told nothing. **Adding is held to a higher bar than recomputing**, so nothing is invented beside a `Transfer-Encoding` header of any shape: `ContentLength.chunked?` answers the RFC 7230 §3.3.1 framing question (is the FINAL coding chunked), which reads `chunked, gzip` as not chunked and looks only at the first TE line — right for leaving an existing `Content-Length` alone, and wrong for inventing one, since the pair gori would then manufacture on every request of a sweep is the canonical CL+TE smuggling primitive the operator never wrote. `FlowRequest.resync_content_length` has always refused on any `transfer-encoding:` line; the fuzz module now states the same rule. `rewrites_content_length?` was narrowed to the rewrite it names while this landed: computed off the whole baseline rendering, it would have reported an ADDED header as "your declared Content-Length disagrees with its own body" — a sentence about a header the operator never wrote — and it had been folding a gRPC prefix reframe into that same claim (#905)
- TUI: `⇧X` clears the **Issues** tab too. #899 rolled the clear-all chord out across the four verbs that empty a tab — History's flows, Probe's findings, the Authorize queue, the ACTIVITY feed — and the Issues list, which holds the hand-written writeups an engagement produces, had no clear verb at all: the key an operator learns as "this clears the tab" did nothing there, on the one tab whose contents cannot be re-captured. It now deletes every issue in the project with its notes, CVSS score and evidence links, behind the same confirm the other four ask, and the prompt names the total. That total is read from the STORE, never from the visible rows: `IssuesView#empty?` answers for the FILTERED list, so gating the wipe on it would have told an operator holding forty issues that there was nothing to clear the moment their filter matched none of them. It is not mark-aware either — `d` is the verb that acts on a marked set — so the marks state's body hint reads `⇧X clear ALL` where the other states read `clear`, and every list state names the key, since the scope does not change with the preview pane. An empty project gets a toast rather than a dialog, the way Probe's and ACTIVITY's answer theirs. The Help sheet's Issues row gains the chord, and `docs/guide/hotkeys`, `scanning`, `authorize` and `proxy` name five members where they named four. The family is now enumerated from the `:wipe` band in the registry rather than a list of ids restated in a spec — the four-id literal claimed a fifth member picking its own letter would fail there, and could not, which is exactly how this gap stayed invisible (#903)

- Fuzzer / confirmations: seven defects a dogfood of #897 turned up, all of them cases where a surface said something that was not true. **A confirmation no longer loses its second clause.** `ConfirmDialog` caps its card at 60 columns and handed each line straight to a renderer that CLIPS at 54, so all three of #897's two-line messages ended in `…` — and in each the clipped half was the consequence: `CLOSE FUZZER` drew "Its template/config, private temporary spool, and eve…" and dropped "ry saved run are deleted.", which is the only warning an operator gets that closing a fuzz sub-tab destroys every run `⇧S` promoted into the project. The card now wraps (in terminal columns, so a CJK message breaks where it is drawn) and grows to hold what it wraps, which fixes the class rather than the three sentences. **A restored run keeps knowing which rows the display dropped.** A row past the window's 64 MiB ceiling is kept as bounded metrics — its payload cut to a 64 KiB preview ending in `… [display truncated]` — and the restore handed the view that window's ROWS rather than the window, so an already-projected row (now small) was re-admitted as a full one: the request pane rebuilt a request from the preview, and `Send to Repeater` seeded those bytes as the request the archive holds in full. **The response detail pane names the bounded display** instead of reporting a run with `keep_bodies: all` as having retained nothing. **`⇧S save` appears in the footer only while the verb would fire** — it is gated on a finished, non-empty, unsaved run, and an unavailable verb is never dispatched, so the key did nothing and said nothing while the hint kept promising it. **A run whose spool failed now says so on the results line** — `archive_failed?` shipped with no reader at all, so the one announcement (the run-start status) was overwritten by the completion toast and a sweep that can never be saved then looked exactly like one that can. **`gori run fuzz list` labels a legacy snapshot `[LEGACY]`**, off the same record method the TUI picker reads, instead of asserting `[H1]` from columns a pre-V24 row never carried — on the very command the picker's refusal points the operator at. And **`gori run fuzz list/show --format json` carries `created_at_iso` / `finished_at_iso`**, so its output can be correlated with `list_fuzz_runs` as strings, the gap History's row emitter already closed (#897, #901)
- CLI: `gori run` refuses a stray positional argument instead of dropping it. `OptionParser`'s default handler is silent, so seventeen subcommands discarded any leftover word and still reported success for work they had not done — `gori run project scope add -p api.example.com note` added the rule and said nothing about `note`, `gori run rewriter add -f a -v b STRAY` printed `Rule #1 added.`, and `gori run capture --project ci STRAY` started the proxy without a word. They now abort naming the argument and the flag its value belonged to, which on these commands is usually an unquoted multi-word value whose tail words arrived as positionals (`--when host:a AND status:500` reports both `AND` and `status:500`). A word after `--` is refused too. **This is a breaking change** for a script that passed a tolerated extra word: such a call exited 0 before and now exits non-zero. The affected commands are `capture`, `colormarker add|preview|color add`, `decoder list`, `intercept enable|disable`, `issues create`, `oast listen`, `probe rules add`, `project scope add`, `project sandbox on|off`, `rewriter add|preview|bindings|preset list|extract add` and `sitemap tag` (#900)
- TUI: one chord clears a tab, in every tab that can be cleared. gori has four verbs that delete a whole tab's worth of project data — History's flows, Probe's issues, the Authorize queue and the Project ACTIVITY feed — and they answered three different things: History had just gained `⇧X` (#898), Probe and Authorize were reachable only from the space menu under `X`, and Activity had picked up `⇧C`. All four are `⇧X` now, with `X` as the space-menu letter, so the gesture is learned once and carries. `⇧X` rather than `⇧C` because of what sits under the shift: bare `x` is bound in none of the four scopes, while bare `c` is live in all of them — `capture.toggle` globally, and `c` dismisses an issue on the Probe list — and a project wipe one shift below the most-pressed triage key in the app is the arrangement to avoid, not the one to standardise on. Each chord is now named where it can be read before it is pressed: the Help sheet gains a row for Probe, Authorize (which had none at all, though its Shortcuts popup already opened onto the section) and the ACTIVITY pane, and every body hint that can fire the key names it — on Probe and History that means the preview-pane and mode-off states too, not just the default list: the scope does not change with the pane, so naming it in one state and hiding it in the other two would have rebuilt the same gap in miniature. `docs/guide/hotkeys` gains the rule, next to the Ctrl one it sits beside. That was the second half of the objection when Probe's wipe came off a bare letter — a destructive key nothing advertises is the same defect one modifier up, and the menu is not an advertisement you read before you press. In Activity the `Clear filters` menu letter moved from `x` to `N` (`history.mark-clear`'s letter for the same word) so that `x Clear filters` and `X Clear activity` no longer sit one shift apart in one menu with nothing but the shift between resetting a chip and deleting the agent audit trail. It also says what goes, since "the queue" understates the identity results that go with it. Probe's clear answers an empty list with a toast rather than nothing at all, the way Activity's already did. Each verb is still scoped to its own tab; `⇧X` also means "enable/disable everywhere" on the Rewriter and Colormarker rule lists, which have no clear-all verb to collide with (#899)

- Project: the event feed records **who changed what**, on every surface. Config changes were invisible to it: a scope rule, the sandbox gate, a host override, a `$KEY` var, a Match & Replace rule or the per-project network pins could be edited from the TUI or `gori run` and the log said nothing, so an audit of the project was missing every change a human made. They are now recorded at the MODEL each surface shares — one site per change covers TUI, CLI and MCP, rather than three copies of which the CLI is the one that gets forgotten — and only once the store has confirmed the write, so a refused rule never appears as a control that existed. Values are named (the pattern, both ends of a dial map) except where they are secret by construction: `$KEY` vars are logged by NAME only and an upstream proxy's userinfo is redacted. Every row now carries an **actor** — `tui`, `cli` or `agent` — reusing the three words `flows.source_surface` already stores rather than inventing a second vocabulary; `a` filters by it, MCP `list_events` returns and filters it, and an agent can finally tell its own writes from the operator's (#864)
- Project: an **Activity** pane — a human window over the #124 event feed the AI already tails. `log_agent_action` has recorded every agent mutation and send since #124 so the activity would be *visible to the human*, but the only reader was the MCP `list_events` tool. The sixth Project sub-tab lists that feed newest-first: agent tool calls and their scope-blocked refusals, job results, and the failures that were logged without ever raising a notification (a `$token` extraction that missed, a response that arrived streamed so the rule never ran, a hook that failed and passed the bytes through unchanged). `s` source, `l` level, `a` actor, `/` text, `↵` opens the flow or session an event names, `⇧X` empties the feed behind a confirm. The notification ring is unchanged: it stays the sparse in-memory interrupt channel while this is the durable log, and nothing moves between them. On a busy or oversized feed the pane holds its place: a cursor sitting on the newest row FOLLOWS it, one parked further down keeps its event and the card border reports `↑N new` above it, a burst larger than one page is folded in rather than resetting a list the operator has paged into, and `↓`'s walk back through a feed grown past the 50k scan window survives the liveness commit that lands every few seconds — so "no events match … in the newest N events" can reach the end of the feed and stops being a claim about a window it never left (#864)
- Cookie: a TUI workbench tab for framework signed session cookies (Flask/itsdangerous, Rack, Django) — the JWT tab's sibling, closing #565's last surface-parity gap. The engine, `gori run cookie` and the `cookie_*` MCP tools already did decode/verify/crack/forge; the TUI only decoded (a Decoder-catalog entry), so a human had to drop to the shell to check or forge a cookie. The tab is two lenses over one session, modelled on JWT: **DECODE** — paste or send a cookie into INPUT → DECODED shows the parsed parts → OPTIONS pins the format (`^A`, auto-detects), the Django HMAC algorithm and a signing salt → SECRET holds a candidate key whose verify verdict (`✓`/`✗`) is live, and `c` cracks it over the field read as a wordlist path or a comma-separated candidate list; **FORGE** — edit the session payload (or the opaque Rack value) and re-sign it under a known/cracked secret into a copyable cookie. A Django SESSION cookie signs under a non-default salt, so the salt/algorithm the OPTIONS pane exposes are threaded through the same engine the CLI drives (`Cookie.verify`/`crack` gained the keywords; the three-argument default-salt path is unchanged) — and because a blank field silently used the *generic* `django.core.signing` salt, a real `sessionid` (the tab's headline target) read as `✗ bad key` under the correct secret; the OPTIONS card now shows a ` salt:signing ` badge whenever the format resolves to Django (auto-detected too, not only when pinned) that flips the field to `django.contrib.sessions.backends.signed_cookies` in one click (`Space → Toggle Django salt`), threading the chosen salt through verify, crack **and** forge together. `Space → Send selection to → Cookie` seeds a session from any selected string. Hidden by default (re-enable in settings:tabs), like the other tool tabs (#863)
- TUI: `/` searches the Help tab, Help reference cards, and Hotkeys editor; Enter jumps from Hotkeys results back to the matching binding (#860)
- Proxy: choose a TLS fingerprint **per send**, not only per destination. #822's `outbound_tls` presets answer "always look like Chrome to this origin"; the question they exist for — *does this endpoint answer differently as `chrome` than as `curl`?* — is an A/B on one host, and asking it meant editing a global rule between two sends, which made the two incomparable and changed the handshake for every other tab and background capture hitting that host at the same time. Now a Repeater tab (`␣T`, a chip on the TARGET band, persisted so a reopened tab sends what it sent before) and a fuzz run (`gori run fuzz --tls-preset`, the Fuzzer's **TLS fingerprint** row, MCP `fuzz_start{tls_preset}`) each name their own; `gori run repeater [send|create|h2] --tls-preset` and MCP `send_request{tls_preset}` do the same for one send, and the result reports which handshake produced it. The override **narrows** the destination policy rather than replacing it: it takes the whole ClientHello shape (`preset`/`groups`/`sigalgs`/`ciphers`/`ciphersuites`/`alpn`/`session_tickets`/`ocsp_stapling`) and leaves the client certificate, the protocol range and `permissive` alone — a fingerprint A/B must not quietly become authenticated-vs-anonymous. It resolves through the same `OutboundTlsRule` every dial already resolves, so it enters the SSL-context cache key by construction and two sends with different fingerprints can never share one handshake. `gori settings tls-fingerprint HOST --preset NAME` prints the JA3/JA4 an override actually sends; presets remain approximations, not byte-exact matches. With no override set, behaviour is unchanged (#844)
- Miner: process hooks reach the parameter miner — `gori run mine --hook './sign.sh'` and the MCP `mine_start` `hook` argument pipe each assembled probe through your own command before it ships, so an app that requires every parameter to carry an HMAC, a signed envelope or a per-request nonce can be mined at all (a raw candidate it rejects before reacting teaches the miner nothing). The command is the same no-shell `ProcessHook` primitive the Rewriter/Decoder/Probe seams use; a hook that cannot run **skips that probe with a reason** instead of sending an unsigned request the miner would then read as a clean negative, and the run continues rather than wedging. The timeout is the one shared `hooks.timeout_secs` budget **per outbound request** — a mine's request count is already bounded by `--max-requests` and its bucket/bisection/confirm tree, so the total hook cost is bounded with it. The TUI config overlay leaves it (and `--wordlist`) at defaults, the same field-free parity gap. The Fuzzer's run-wide `--encode`/processors catalog stays pure-transform on purpose: an exec belongs on the per-position `§value¦exec:…§` chain, which already carries the failure channel and up-front argv validation a closed processor catalog cannot (#846)
- Hooks: finish the "a hook runs when you SEND, not when you look" contract inside the fuzz engine (#851 follow-ups). A template with one hook marker and one failing pure marker now refuses **before** the hook fires — pure chains are ordered first, so a refusal decidable without a side effect is decided without one. `Generator#baseline_raw` is memoized, so `Plan.build`'s three structural questions fork an `exec:` chain once, not three times. The Repeater send path and `Fuzz::Plan` now share one chain validator (it lives in `fuzz/`, the TUI calls it) and one refusal sentence, and `WsScript#apply_chains` forwards `run_hooks` like the other composites (#852)
- Settings profiles: a shareable profile can carry commands, and both ends now say so. Five sections can hold one — `rewriter` rules with `op: pipe`, `scan_rules` with `kind: exec`, a `decoder` chain's `exec:` step, `statusline.command` (a `/bin/sh -c` on a timer) and `editor.command` — and they still export like any other setting, because a team standardising on one re-signing hook is what hooks are for. But `gori settings export` now reports how many it wrote on stderr, and `gori settings import` lists each one with its name, mechanism and command before writing anything, then **refuses until you pass `--allow-commands`** (no prompt, so a scripted import stays scriptable). `--dry-run` prints the same list; narrowing with `--sections` narrows it too, so an import that arms nothing asks for nothing. `gori settings sections` marks the five, and the listing escapes anything in a name or command that could make the line read as something other than what runs (#842)
- Settings profiles: `hooks.timeout_secs` can travel in a profile. It was serialized into every export but missing from the section registry, so importing one warned `unrecognised section(s) ignored: hooks` and dropped it — a profile carrying `pipe` rules silently lost the timeout that bounds them (#842)
- Retest: a diff row reaches Issues and Notes — `⇧F` files the selected endpoint as an Issue prefilled with both projects, both sides' answers and what moved, `n` records the same as a Note in one keystroke, and the capture on the open project's side is linked as evidence rather than copied. A coverage-gap row files as `info` and says the newer capture never requested the endpoint, so it cannot claim a removal the diff never observed; `gori run diff --format json` carries that same sentence on every row (#845)
- Issues: score a finding with CVSS and let the severity follow. `Space` → **Set CVSS** (or `↵` on the issue form's `cvss` row) opens a calculator you can either type a vector into or build one in — CVSS **v3.1 or v4.0**, each version keeping its own selections; headless it is `gori run issues --cvss` and the MCP `cvss` argument, all of which refuse a string they cannot score. Adds `cvss:>=7` filtering, CVSS-aware Markdown/JSON exports, and real CVSS scores in SARIF's `security-severity` (#575)
- Rewriter: response-modification presets — one keystroke installs the Burp-style options every tester writes by hand (unhide hidden form fields, enable disabled/readonly controls, remove `maxlength`, strip client-side validation, drop CSP, drop security headers, disable SRI). A preset installs ordinary, visible, editable, disable-able Match & Replace rules through the same write path as manual authoring — nothing hidden, nothing magic — so they can be edited or deleted like any other rule. `p` on the Rewriter tab, `gori run rewriter preset list|add <name>`, and the MCP `list_rule_presets` / `create_rule_from_preset` tools all install from the one static catalog; the regex rules stay conservative about markup and never run a command (#821)
- External process hooks: pipe bytes through your own command instead of a plugin API — a Rewriter `pipe` op, a Decoder chain `exec:` step, and a Probe `exec` rule, all one primitive. The command is exec'd directly with no shell and runs with YOUR privileges (unsandboxed, the same trust level as any Rewriter rule); every run has a hard timeout (`hooks.timeout_secs`, default 5s) and a 32 MiB stdout cap, and on timeout, non-zero exit, failed spawn or oversized output the original bytes pass through unchanged with a notice — the proxy never stalls on a hook. The MCP `decode` tool refuses `exec:` steps: it stays pure compute. A hook runs when you SEND, not when you look: the surfaces that replay a `§value¦chain§` to DRAW one — the `^Q` chain editor's preview, a rebuilt Fuzzer result row, the Repeater's Content-Length reflection — withhold the `exec:` step and say so, and reopening a project restores every saved Repeater tab and Decoder sub-tab without firing their commands. The Decoder tab's own chain stays live by design (#818)
- Retest: diff two projects at endpoint scale — what is new, gone, or answering differently since the last engagement. A Diff sub-tab under Target, `gori run diff` (text/json/md), and the MCP `diff_projects` tool; endpoints are keyed by the Sitemap's folded template, and an endpoint the newer capture never requested is reported as a coverage gap rather than as removed (#824)
- Proxy: per-destination outbound TLS fingerprint control — `groups`, `sigalgs`, TLS 1.3 `ciphersuites` and an ordered `alpn` list on `outbound_tls`, plus `chrome`/`firefox`/`safari`/`curl` presets, so an origin's anti-bot layer sees a browser-shaped ClientHello instead of gori's OpenSSL one. `gori settings tls-fingerprint` prints the JA3/JA4 that actually goes out; presets are approximations, not byte-exact matches (#822)
- gRPC: point a project at a `protoc` descriptor set (`Project → Project settings → Proto schema`, or drop one in `~/.gori/protos/`) and captured protobuf renders as named, typed fields — the request path `/package.Service/Method` is the binding. Undeclared field numbers and wire/schema disagreements are still shown, the raw wire tree stays beside the lens on every surface, and with no descriptor set loaded nothing changes (#823)
- Fuzzer: sweep a schema-known gRPC field instead of the octets of a varint. `gori run fuzz --field role`, the MCP `fields` argument and the Fuzzer tab's **gRPC field(s)** row name a DECLARATION — a field name, a path into a nested message (`profile.age`), a field number, `tags[1]` for one occurrence of a repeated field — and each payload goes through that declaration on its way to bytes, because `-3` is a different set of octets as `int32`, `sint32`, `bool` or an enum. Every byte outside the fuzzed field is copied from the capture and the 5-byte gRPC length prefix follows the message it now describes. A field the schema does not declare, one whose wire type the declaration contradicts, and a payload the declared type cannot hold are all refused before the first request (#843)
