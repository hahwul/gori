# Changelog

## Unreleased

- Colormarker: a custom colour whose write did not reach disk stayed live in memory anyway — offered in every project's picker, painting rows, blocking a retry as a duplicate and landing on disk at the next unrelated save, all under a message saying it was not written; a refused delete failed the same way in reverse. Promoting a rule from the EDIT card now moves the highlight with it and says so, and `gori run colormarker move --scope=global` distinguishes a refused write from a rule already at the top of its block (#802).

- `y` with nothing selected copies the WHOLE pane, not the caret's own line: the History detail's Request/Response, the Project description, an Issue's notes and the JWT INPUT pane in READ all fell back to one line, so each disagreed with the `^Y` beside it and with every other read pane. In the OAST callback detail the same key was dead altogether, along with the `x` beside it in the footer — that pane swallowed every key it did not handle itself.

- A `--wsdl` import source: a WSDL 1.1 service description becomes one SOAP request template per operation on every SOAP port it publishes, from the palette (`Import: WSDL`), `gori run import --wsdl PATH`, and the MCP `import_flows` tool. SOAP 1.1 and 1.2 bindings both, with bodies built from the XSD inline in the document; external schemas are never fetched and a `<!DOCTYPE>` is refused.

- The Fuzzer sweeps a WebSocket exchange: mark `§…§` positions in the outbound frames (and in the handshake) and each payload runs one full RFC 6455 session, with the inbound frames matched as the response body and the close code on every row. `gori run fuzz --repeater N` and MCP `fuzz_start` seed a WebSocket session's frames instead of refusing it, `--message` / `--message-frame` / `--idle-ms` / `--ws-keep-key` author them, and `--ws-http-only` sweeps the handshake as a plain request (#795).

- The NEW / EDIT ISSUE card's severity steps with `←`/`→`, the way every other cycler in the TUI does; `⇥` now moves between the title and the severity row rather than being the only control that changed it (#789).

- The History detail's MESSAGES pane shows a WebSocket frame's shape, as `gori run show` and the Repeater transcript already did: a PING, a PONG, a CLOSE with its code and reason, a message reassembled from several frames, an RSV bit and a client frame sent UNMASKED were all one indistinguishable `«binary Nb»` line in the one place an operator reads while working a socket (#787).

- The two pairs of identically-titled cards say which list they are: Settings' ENVIRONMENT and HOSTNAME OVERRIDES are marked `global`, the Project tab's ENVIRONMENT and HOST OVERRIDES `project` — the global pair is layered under the project one, and neither said so (#787).

- A Colormarker or Rewriter rule named in wide characters (Hangul, an emoji) drew its own row over itself: every field after the name was placed by counting CHARACTERS, so the filter behind it landed inside the name and the two-column glyphs whose lead cell it overwrote came out blank. Those rows now advance by the columns they actually drew; the OAST callbacks table's PROVIDER column takes the width it needs out of whatever DESTINATION does not, instead of a fixed 17 with a hundred blank columns beside it; and a card's border annotation (`8/9 enabled`, `REQ`, a bare count) is spaced clear of the hairline it used to butt into (#787).

- A truncated brotli body decoded to exactly 65,536 bytes and a multi-frame zstd body to its first frame only; both now decode in full, which the detail view, the Comparer and every headless read of a decoded body see (#786).

- The Decoder reads brotli, zstd, MessagePack and CBOR, and a MessagePack or CBOR body renders as JSON in the detail pane when its `Content-Type` says so. The JSON is a projection — `$bin`, `$tag` and `$ext` name what JSON cannot hold — never bytes to send back (#786).

- A `socks5` listener mode: the client names its destination in an RFC 1928 handshake and gori intercepts what follows, for a client that can be pointed at a proxy but not an HTTP one. NO-AUTH and CONNECT only; a `CONNECT` to any fixed-destination listener is now refused (#786).

- `network.strip_alt_svc` removes the `Alt-Svc` fields advertising HTTP/3 before the client sees them, so a browser cannot switch to QUIC and leave the proxy unseen. Off by default; `Alt-Svc: clear` and non-h3 alternatives are never touched (#786).

- `gori mcp --install-hermes` writes the server into Hermes' `~/.hermes/config.yaml` (or `$HERMES_HOME`), the first YAML client alongside the JSON and TOML ones. Sibling servers, their `env:` keys and the comments around them are left as they are. (#785)

- The History and Target filter bars are clickable: `v:` opens the view picker, `f:follow`, `g:fold` and `⇧S scope` toggle what their chords do, and a click on the query readout beside them opens the filter for typing. (#782)

- History views: `v` picks a named filter the list narrows to, and it is a **mode** rather than a query you retype. `src:` made the common scopings expressible; this makes them stick. The view is ANDed **over** the filter bar, exactly as the `⇧S` scope lens is — so `/ status:5xx` refines the view instead of replacing it, which is the whole difference between a mode and a query. A lowercase `v:name` chip sits left of `f:follow` — abbreviated where the name is wider than the row (`History + Repeater` shows as `v:history+rptr`) — and the choice persists per project across restarts.
  - Seven built-ins ship everywhere, on two axes the picker deliberately does NOT pre-combine. **Source**: `All`, **History** (`src:proxy` — only traffic a client really sent) and **History + Repeater**. **Protocol**: `WebSocket`, `gRPC`, `SSE`, plus `Errors` (`status:>=400`). A view named `WebSocket` that also excluded an imported socket would be lying about its own name, and the axes compose through the lens anyway — pick `History + Repeater`, type `proto:ws`, get the intersection. `History` is `src:proxy` and deliberately not `-src:gori`: those are different sets, and the negative spelling would pull somebody else's imported capture into "History".
  - **A project now opens on `History + Repeater` rather than everything.** The flows gori's own crawler, fuzzer and importer wrote are not evidence about the target, and a list that mixes them in is the defect `src:` exists to fix — a default just fixes it for the people who never type the term. Repeater is IN because a resend is the tester's own deliberate act on a real endpoint. One exception, and it is the caveat below made load-bearing: a project captured before provenance was recorded opens on `All`, because `src:` matches those rows in neither direction and the ordinary default would open an old engagement on an empty list. A brand-new project still gets the first-run card, not "no flows match the History + Repeater view" — naming a filter that excluded nothing is useless when there was nothing to exclude.
  - Save the filter you already typed under a name, in either of two stores — **project** (this engagement; where `host:api.acme.test scope:in` belongs) or **global** in settings.json (every project; where a `src:` view belongs) — the same two-scope split colour rules use, minus the per-project enable override, since a view is either the one you picked or it is not. The picker opens ON the view that is on — it is a mode selector, not a load-a-recipe library — and `^E` loads a view's query back into the filter bar to edit while `^X` deletes one; saving a name that already lives in the other scope MOVES it rather than leaving two a `--view` would have to choose between.
  - **A view's query is validated when it is saved, not when it runs.** One whose every term would be dropped compiles to the match-all EMPTY filter, `QL.and` folds that away, and the result narrows NOTHING while the `v:` chip asserts a filter — the same failure `QL.reject_empty?` exists to refuse for the bar, and the direction that matters on a security proxy. Refused at all three write surfaces, and refused again at apply time, because a view still arrives from a peer's settings.json or a hand edit. A control character in either half is refused for the same one-validator reason: both the name and the query get PRINTED, and a newline in a name breaks `gori run views list`'s one-line-per-view shape while an ESC emits its own sequence — neither is typeable in the TUI's prompt, and both are reachable from the CLI, from MCP and from a hand edit.
  - Views are a project object, not a TUI convenience: `gori run views` (list/add/rm/rename/set/scope) and `gori run history --view NAME`, MCP `list_views`/`create_view`/`update_view`/`delete_view` and `list_history{view}`. Addressed by NAME, unique within a scope, resolving **project → global → built-in** on a collision — the precedence project env vars and host overrides already follow. An unknown name is refused and names the ones that exist, rather than quietly listing the whole project.
  - The empty state says which control emptied the list, headless included — `gori run history --view` answers `no flows match "status:200" in the "Errors" view` rather than a bare `no flows`, because "I saw no traffic" and "a standing filter excluded it" must not read the same. A `src:` view on a project captured before gori recorded provenance matches nothing however much traffic it holds — those rows are in neither direction — so the note names that instead of leaving the operator at "no flows". A view deleted from another gori drops History back to All and says so, rather than filtering by one that no longer exists.

- History says where every flow came from, and a Repeater send is one of them. **Six producers were already writing into `flows` and nothing on the row told them apart**: the capture proxy, MCP `send_request` (whose `record_history` defaults to TRUE), a Discover crawl (on by default), an opt-in `--record-history` fuzz sweep or repeater send, and `import`. History is read as evidence, so "the target answered this" and "gori's own Repeater elicited this" being byte-identical is the same class of defect the `STUB` marker fixed one layer down — that one about a response gori FABRICATED, this one about a request gori SENT. A `src:fuzzer` hit returning your own traversal payload was, in the list, a `.env` the origin serves.
  - A new **SRC** column carries the tool (`PROXY` · `RPTR` · `FUZZ` · `CRAWL` · `IMPRT` …), and the detail pane spells it out under the request — `sent by gori — repeater (tui) #4` — naming the surface and the session behind it. SRC is granted FIRST in the right-hand cluster, so it is the LAST to drop on a narrow pane: a marker that falls off a small terminal is a marker that lets someone screenshot a resend as captured traffic, which is why `STUB` sits inside a fixed-width column for the same reason.
  - QL gains `src:` on all three surfaces — `src:proxy` to read History as traffic that really happened, `src:repeater`/`src:fuzzer`/… for one tool, and `src:gori` for every request gori put on the wire. `src:gori` is built from the enum rather than a hand-written list, so a workbench that learns to record joins it by existing; an IMPORT is deliberately in neither (`-src:proxy` keeps it, `src:gori` does not) because gori never sent it. The column's short tags are typeable (`src:rptr`), `source:` is accepted as the long spelling, and a colour rule takes the same term. `list_history`/`get_flow` and `gori run history --format json` carry `source` on every row (`null` included), plus `source_surface` and `source_ref` where there is one; the text listing gets a `[repeater]`-style chip.
  - **TUI Repeater sends are now recorded by default** (Settings → General → *Record Repeater sends*), because the tester driving a request by hand was the one whose evidence went missing. The status line names the flow it wrote. `gori run repeater send --record-history` (off) and MCP `send_request{record_history}` (on) keep their explicit per-call arguments, so no script's behaviour moves under the setting. WebSocket sends and send-groups are not recorded and say so once.
  - **Authorize's passive replay stops feeding itself.** Its own comment said a self-loop was structurally impossible "because nothing writes them back with `insert_flow`", and the Repeater recording by default ended that: without a guard, every `^R` would fan out into one shadow request per identity, and so would an agent's `send_request` beside it. `Passive` now declines a gori-originated flow by name (`sent by gori, not the browser`) on the unattended path ONLY — a human who points at a flow still gets it replayed, and an imported one is not caught at all, since it describes a real endpoint somebody captured.
  - Provenance is NOT backfilled. `short_circuited` could take a `NOT NULL DEFAULT 0` in V5 because 0 was the truth for every existing row; that argument does not hold here, so a flow captured before the V17 columns shows `—` and matches `src:` in NEITHER direction, the way a Pending flow falls out of `status:` and `-status:`.

  - **Active-traffic gate**: the Fuzzer's `--race-warmup` / `race_warmup` reached the socket with no `Outbound.sweep_block` decision — the one send in `fuzz/engine.cr` that was not gated, so a warm-up could reach a path an EXCLUDE rule or the Sandbox allowlist carves out.   - **Reporting a write that did not land**: `Colormarker#add`/`#update`, `Rules#move`, `Store#move_rule`, three repeater metadata writes, `Store#update_probe_custom_rule`, the three session renames, and MCP `oast_release` all discarded (or never had) the store's commit answer and reported success over a rolled-back batch. `insert_extract_rule` was worse than silent: SQLite does not reset `last_insert_rowid()` for an ignored `INSERT OR IGNORE`, so a name collision answered a stale non-zero rowid and `Bindings#add` reported a binding saved that was never written. - Authorize: a new tab that replays a captured request under a set of identities and reads each response against a baseline, to find broken access control. Identities are header overlays saved with the project, `p` turns on passive replay of what the browser touches, and the same plan drives `gori run authorize` and the MCP tools (#707, #710)
- Fuzzer: a payload spliced into a query-string or form-urlencoded body value is URL-encoded by default, on all three surfaces. `--auto` found the position but did not encode for it, so `gori run fuzz --auto --preset xss` put a raw `<script>alert(1)</script>` in `?q=` — the space ends the request-target and the origin answers 400 to a request that never carried the payload under test, which is why every playbook carried the footnote "add `--encode url`". Path segments, JSON and raw bodies, headers and cookie values still go on the wire byte-verbatim; an explicit `--encode`/MCP `processors` pipeline or a per-position `¦chain` replaces the default rather than stacking on it, and `--no-encode` / `no_encode:true` sends the query/form positions raw
- Fuzzer: a Race condition (last-byte-sync) attack mode over HTTP/1.1 — N connections held at the final byte and released together — on all three surfaces, with an optional warm-up (#705)
- Project settings: the Project tab's overview folds its rows instead of dropping the ones it had no room for (#691)
- TUI empty states: every tab that can be empty draws a figure above its card, the tabs that answered with one grey line get a card (Discover, Comparer, Miner, Sequencer, OAST, Project's Description/Scope/Host overrides/Env), and the figures and cards are redrawn and sized to fit the panes they are actually in (#691, #692, #693, #698, #701, #702)
- Sub-tabs: every workbench strip gets a ⌕ picker, opened with `f` from any chip, that matches a chip's number and the content behind it — wire bytes, a note body, a JWT claim — not just its label (#694, #695, #696, #697)
- TUI: Help's shortcut and QL references open as palette cards over the pane you are on instead of a tab jump, the OAST payload and listener actions ask which provider rather than refusing, and the binary-body hint names the real `^X` chord (#685, #686, #703, #704)
- Sequencer: the SAMPLES pane follows the tail while a collection streams — the rule was there in a comment but the code only ever held a cursor already on the last row — and stops following the moment you scroll up, so reading a sample mid-run no longer fights the next four hundred (#711)
- MCP arguments: an integer a client SUPPLIED but gori cannot read — `max_requests: {"n":1}`, `concurrency: [5]`, `limit: 5.9`, `rate: "fast"` — is refused by name instead of falling back to the tool's default. `fuzz_start` used to answer `isError:false` and sweep with no rate limit and no request budget; the pagination readers quietly re-paged from row 0. Every such argument is now read BEFORE the work it accompanies, so a refused `max_body_bytes` no longer arrives after the request is on the wire and the repeater row is written, a refused `probe_scan{limit}` no longer throws away a whole active scan, and a refused `stop_job{wait_timeout_ms}` no longer reports failure for a job it already stopped. A number merely too large for Int64 still clamps, since `1e19` is how "no limit" is spelled. This is the integer half of the contract already pinned for strings and booleans (#724)
- MCP: `rate` is a number rather than an integer on `fuzz_start`/`mine_start`/`sequence_start`/`discover_start` — the engine's `rps` and `gori run --rate` have always been fractional, so `rate: 0.5` (one request every two seconds, the pacing a fragile target needs) was the one thing this surface could not ask for (#724)
- MCP: a nested integer in a fuzz payload set is read in every encoding the top-level arguments accept, or refused by name. `{"numbers":{"from":1,"to":100,"step":2.0}}` swept 100 candidates instead of 50 and `{"brute":{"min":1,"max":3.0}}` tested length 1 alone, both reported clean — while the string spellings of the same mistakes had always refused loudly (#724)
- MCP: `send_request{h2_fields}`, `intercept_forward_edit` and `fuzz_start{race_warmup}` no longer coerce their wire-byte arguments from a scalar — `12345678` became a string that decodes to six octets, so gori sent bytes the caller never named. The identical `body_base64` was already refused on `send_request`'s url path, so the same call was an error on one path and a send on the other (#724)
- MCP: `fuzz_results` rows carry `matched`, and `matched_only` actually filters. The stored set stopped being matched-only when re-sent, retried and truncated rows started being kept, so the page mixed matches with non-matches and carried no bit that told them apart — while the schema still called the filter a no-op (#724)
- Internals: one shared list-viewport derivation replaces forty copies across the TUI, fixing seven scroll defects on the way — an Intercept queue that drew nothing after most of a scrolled hold list was forwarded, a hex editor that collapsed to one row mid-edit, and five lists that stranded their first rows off the top of a pane. The layering contract is an executable spec now instead of a grep recipe pasted into two documents (#710)
- Miss Ring: eyebrows as an expression axis, four more faces, reactions that peak and then settle, and idle gestures three times as often (#684)
- Export: a HAR now carries a WebSocket flow's messages. The `101` handshake is written as itself with the captured transcript beside it in Chrome DevTools' `_webSocketMessages` field — direction, opcode (control frames included), exact bytes (base64 when not valid UTF-8) and millisecond timestamps — and `gori run import --har` restores them onto the flow, so the evidence survives a hand-off and a re-export. A socket with an empty transcript is still skipped and counted
- Docs: an Authorize guide in both languages wired into the guide, CLI, MCP and scripting references, a favicon themed to the logo gradients, and a photographic ring hero on the landing page (#706, #708, #710)
