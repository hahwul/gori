# Changelog

## Unreleased

- Issues: an issue can carry a **retest** — the ordered Repeater sends that reproduce the finding, each with a role (`setup` / `baseline` / `variant` / `control` / `cleanup`) and at most one expected result — so "send #4 to log in, then #5 should answer 403, and #6 is the control" stops being prose in the write-up and becomes something CI can run. Links say what material is related and frozen evidence keeps the bytes that proved it; neither can be *executed*. `Space` → **Retest…** (`⇧R`) on an Issue opens the card: `a` picks a linked Repeater session, its role and one assertion — a status (`status:403`, `status:2xx`, `status:200-299`), a JSON field (`json:data.role=admin`, `json-absent:data.token`) or a comparison with the baseline (`body:same` / `body:diff`) — with an empty assertion meaning "record the outcome", which is what a login or a cleanup step wants. `⇧J`/`⇧K` reorder, `e` edits, `d` removes, `r` runs (`⇧R` runs while permitting the cleanup steps after a refused send), and `↹` swaps the card between the plan and the last run's result table (role, session, expected, actual, pass/fail per step). A step sends whatever its Repeater tab holds at the moment of the run — that is the difference from freezing, which keeps the request as it *was* — and the tab's own stored response is never overwritten: each send is recorded in History as `src:retest` carrying the issue and step number, so `↵` on a result row opens the exact response that row reported, months after the tab moved on. Every send passes the project's scope and Sandbox gates; before a batch containing a state-changing method gori names the exact request count and asks, because each of those re-runs its side effect on the target. Once gori **refuses** a send the rest of the run is skipped — cleanup steps included, unless the operator allows them — and every skipped step still gets a row saying why, so a partial run can never read as a pass. A `setup` step that fails halts the measurement steps but still lets cleanup run. A `body:` comparison is `inconclusive` rather than a pass both when nothing has anchored it and when the last `baseline` step **missed its own expected result** — a baseline that did not establish its reading anchors nothing, so a variant compared against the 403 error page a `status:200` baseline was handed cannot report "the body is unchanged" about two error pages — and a `json:` assertion against a body that is not JSON is `inconclusive` too, so an HTML error page cannot satisfy `json-absent:`. The verdict is `pass` only when every step ran and every assertion was decided, and `blocked` outranks `fail` — a run gori refused to finish is a fact about the scope configuration, not about the target. The Issue detail grows a one-line summary only once it has a retest, and the newest 20 runs per Issue are kept. Headless, `gori run retest add|steps|update|move|remove|clear|run|runs|show|forget` (with `run` exiting `0` only on `pass`, so a fix's CI job can gate on it) and the MCP tools `list_retest_steps` / `add_retest_step` / `update_retest_step` / `move_retest_step` / `remove_retest_step` / `run_retest` / `list_retest_runs` / `get_retest_run` / `clear_retest_steps` / `delete_retest_run` do the same; `list_retest_steps` resolves every step against the project, so a caller knows what will be sent and which steps change state without sending anything, and `get_issue` carries a `retest` object (step count, last verdict) on an issue that has one — so reading a finding already says whether a reproducible check exists and what it last answered (#1036)
- Issues: an exchange can be **frozen** as immutable evidence, so what proved a finding survives the Repeater's next send and History's retention sweep. A link is a pointer, and both live sources are mutable: a Repeater tab holds one response and the next send replaces it, while a flow is one sweep from `(gone)`. `Space` → **Link & freeze…** from History, the History detail or the Repeater links the exchange to an issue and copies its request, response, status, timing, protocol, error and truncation state in the same transaction (`+ New issue…` files the issue and freezes in one go); `f` on a live row of an issue's RELATED card, or in its LINKS card, freezes an existing link. The RELATED card lists LIVE and FROZEN rows apart. `↵` on a frozen row opens its read-only request/response viewer. Once the project has a snapshot, the optional **Evidence** tab exposes the full archive with filters for Issue, host, method, HTTP status, confirmation, source and date. From there you can open a linked Issue or surviving source, compare two snapshots as before/after, make a redacted copy or JSON export, duplicate the frozen request into Repeater without sending it, and link or unlink Issues without changing the stored bytes. A snapshot carries SHA-256s of its stored request and response, can belong to multiple Issues, and remains as an easy-to-find orphan when its last Issue link is removed or an Issue is deleted. Only its explicit delete removes it, after a confirmation names every affected Issue link. A never-sent Repeater tab is refused rather than frozen request-only, and so is a flow whose response has not landed; a copy over 1 MB shows its byte cost first, and the project's evidence is bounded at 256 MB. A Repeater copy pairs the tab's saved request with the last response the store holds (a successful send's), and a WebSocket copy is the handshake without the frame transcript. The History detail's stats line and the Repeater's RESPONSE border say `frozen ×N` once a copy of the open flow or tab exists. Markdown and JSON exports and MCP `get_issue` list each copy's provenance and hashes, never its bytes. Headless, `gori run evidence freeze|list|show|link|unlink|delete` and the MCP tools `freeze_evidence` / `list_evidence` / `get_evidence` / `link_evidence` / `unlink_evidence` / `delete_evidence` do the same. `gori run evidence` and `list_evidence` with no Issue named list the same project-wide archive the tab shows, orphans included, so a snapshot whose last link is gone is still findable without knowing its id. An agent that confirms a finding and retests the fix freezes twice and the issue holds both; `show` / `get_evidence` return the bytes the way `get_flow` does, credentials redacted unless asked (#1038, #1039)
- Evidence: a **safe export** mode that replaces the values a *redaction profile* names inside request and response BODIES with a keyed placeholder, `[REDACTED:3f1c9ab4]`, so a flow can go into an issue, a report, a CI log or an agent transcript without being sanitized by hand. Equal values share a tag — the token in the request is visibly the token in the response, with neither disclosed — and the tag is an HMAC under a secret minted once per install rather than a digest of the value, because a truncated hash of a 4-digit PIN or a wordlist password is recovered in milliseconds and would make the placeholder itself the disclosure. A profile matches JSON member names at any depth, RFC 6901 pointers (with `-` read as "any array index"), form keys, and regexes where capture group 1 is what goes; profiles live per project AND globally, most-specific-first, because "never export a `password` field" is the operator's policy while "this target calls it `pwd_hash`" is engagement data that must not follow them into the next one. `gori run show --redact` sanitizes the flow ONCE, so every `--format` it can print is covered — `raw`, `text`, `json`, `har` and the six request-as-code serializers — and `gori run history --format har --redact` does the same for a whole result set; `--redact-preview` lists what would go without printing the document, `--no-redact` is the explicit path back, and the count, the profile and the caveats all go to STDERR so STDOUT stays the artifact. The stored bytes never change: History, the Repeater, the Comparer and `get_response_body_chunk` keep reading the capture exactly, and a replay after an export is byte-identical to one before it. A sanitized head is repaired to describe its new body (`Content-Length` rewritten; `Content-Encoding`/`Transfer-Encoding` dropped where the body had to be decoded to be read), a body gori cannot read — not valid UTF-8, or `multipart/*` — is withheld WHOLE rather than half-sanitized, and a body that does not parse falls back to a conservative text pass that still honours the profile's field names plus two shapes that are never anything else (a JWS/JWE, a PEM private key). Turn it on once with `gori run redact default on` and the TUI's `Space → Y` copy menu (heading: `COPY REQUEST AS · SANITIZED (3)`, WebSocket frames included) and MCP `get_flow` (a `body_redaction` object naming the profile, the counts and what it did NOT look at) follow. Heads, URLs and query strings are deliberately out of scope, and every surface says so rather than letting "sanitized" stand for more than it is (#1035)
- TUI: the Evidence tab's REQUEST column starts where its header says. The rows drew the request two cells left of the REQUEST heading, inside the CONFIRM column's last cell — so the widest confirmation, `FALSE-POSITIVE`, lost its final letter under the method and path of every row that carried it
- TUI: the History/Issues/Probe drill-ins and the Comparer's jump-by-change now step with one pair, `⇧N` / `⇧P` — `⇧N` used to mean forward in a drill-in and backward in the Comparer, and `⇧P` was bound nowhere. The status line stops naming them when there is nowhere to step, such as a flow opened by id that the current History view filters out (#1040)
- Colormarker: a History row no longer inherits a deleted flow's colour. `flows.id` is a reusable rowid, and both the row-colour memo and the engine's store-tier answer cache were keyed by the bare id and dropped only when a response landed — so deleting flows (or clearing History, which restarts the numbering outright) left the next capture painted by a rule it does not match, for the rest of the session. History's PATH memo is keyed the same way and went the same way, drawing the new flow under the deleted one's path
- Colormarker: the rule editor's `matches N of M recent flows` line no longer under-reports what a GLOBAL rule would paint. Every global rule resolves before every project one, so a project rule can never claim a row from a global candidate — but all three surfaces counted the whole merged list as sitting ahead of a rule that does not exist yet, and the form said `0 would be painted · N claimed by an earlier rule` for a rule that in fact paints all of them. `gori run colormarker preview` and MCP `preview_color_rule` take `--scope`/`scope` for the same reason and report which one the answer is for. The editor re-scans when the scope row is cycled — not only when the condition changes, which left the band showing the other scope's number — and draws that line the moment it opens on an existing rule, rather than staying blank until the first keystroke
- Colormarker: duplicating a rule keeps the original's enabled state, the way the Rewriter's duplicate already does. A copy was created armed regardless, so duplicating a rule an operator had deliberately switched off started painting rows on the next frame — and for a global rule the copy's state is the LIBRARY DEFAULT, so a rule switched off in this project came back on in every other one. The highlight now follows the copy to the end of its scope block
- Colormarker: the rule editor shows the same caveats `gori run colormarker` prints on STDERR and MCP returns in `notes` — that `host:` is a substring rather than a DNS-label glob, that a flow with no response has no status yet, what a `body:` term really scans, and what `scope:` follows. `Colormarker.advise` was written to be worded once for all three surfaces and the TUI was the one that never said any of it
- CLI: a wordlist path that names a TERMINAL is refused instead of blocking forever — `fuzz -w /dev/tty`, `mine --wordlist` and `discover --wordlist` each hung with no output, echoing whatever was typed into the scrollback. The seven stdin sources gori falls back to when no flag names one (`fuzz`, `mine`, `sequence`, `decoder`, `jwt`, `cookie`, `notes`) also report an unreadable stdin — fd 0 closed by a cron or systemd unit — as a sentence rather than a Crystal backtrace (#1034)
- CLI: a refusal the arguments alone settle now comes before the pipe is drained rather than after — `repeater create --tls-preset=bogus`, an `authorize` naming no flow id or `--query`, and `rewriter add --op=short_circuit --part=ws` each used to consume a generator's entire output (and, for the first two, open the project) before reporting a typo. `rewriter add --response-file` pointed at a directory now prints a sentence instead of a twelve-frame backtrace (#1034)
- CLI: `gori run colormarker update <id>` edits a rule in place — `--when`, `--color`, `--style`, `--name`, each optional and defaulting to the rule's current value, in either scope. Editing existed on MCP and in the TUI form only, so a headless operator had to delete and re-add; that is not the same action, because a colour rule's POSITION is its meaning and a re-added rule lands at the end of its scope block. The global branches of `update`, `rm`, `enable` and `disable` now check the rule against the list on disk — the one the mutator acts on — so a peer's write between start-up and the mutation can no longer turn "already gone" into "settings not writable"
- Docs: the `run colormarker` reference said `body:` never matches, and that there is no `header:` / `size:` / `dur:` / `url:` / `stub:`. A colour rule has spoken full History QL for some time: a term the captured row can answer is matched in memory, the rest resolve against the project database in one batched query per repaint. The page now says that, along with the four caveats gori actually warns about and the three refusals it makes
- Decoder: a defect pass over the tab, its engine and the readers behind it. A Java stream whose `classDesc` slot holds a back-reference with the top bit set — ten bytes of a hostile cookie — raised `OverflowError` out of the reader instead of answering "no such handle", and the readers' "never raise" contract is what `gori run show --format json`, MCP `get_flow` and the flow detail pane inherit directly. The handle is now read as the signed int the grammar says it is, and the last-resort net in all three binary-document readers (`Serialized`, MessagePack, CBOR) catches every exception rather than the two classes its author happened to expect. `gori run decoder list` MEASURES the category and direction columns as it already measured the name: `serialization` is 13 characters against a hard-coded 11, so every msgpack/cbor/java/viewstate/php/pickle row sat two cells right of the other seventy. MCP `decode` names the encode surprise for the COMPRESS and ESCAPE families too, not only `-encode` — `gzip`, `deflate` and `raw-deflate` compressed and `html`/`xml` escaped, each with `isError:false` and nothing said — and the note now names the converters that actually undo what ran, IN THE ORDER THAT UNDOES IT (`gzip > base64` is undone by `base64-decode > gzip-decompress`, not the other way round), staying quiet for a one-way transform that has none and for a token that spelled its direction. The Decoder's ⌕ picker keeps the DECODED half searchable however long the pasted input is — a blob past the budget used to crowd it out entirely, so the `admin` in a 4 KB token's claims was unreachable by the picker that exists to reach it — and cuts each half before joining instead of copying a 32 MiB decode into a fresh string to keep its first 2 KB. The chain autocomplete stays inside its field: a match as wide as the card overran it and painted outside the pane (#1011)
- Cookie: `gori run cookie --verify` / `--crack` and the MCP `cookie_verify` / `cookie_crack` tools read the Django HMAC algorithm off the cookie's own signature length (HMAC-SHA1 is 20 bytes, HMAC-SHA256 is 32) when `--algorithm` is left unset, instead of always assuming the `sha256` default. A real `sessionid` from an app still on SHA-1 was reported `invalid` / uncracked even with the correct secret in hand — the same silent wrong answer the Cookie tab's algorithm badge already spared TUI users; the three surfaces now share one detector. An explicit `--algorithm` is still validated and honored, and `--forge` (which mints and has no input cookie) keeps the `sha256` default
- Sequencer: six defects, all of the shape "a number that looks right and answers a different question". A `position` descriptor whose range is empty or reversed (`--position 40:8`, MCP `position: "40:8"`) is refused before the first request instead of running a full collection in which every sample misses and reporting `CRITICAL · no usable tokens` — a verdict about the origin's entropy from a descriptor that read none of it; only the TUI card caught it, and the check now lives in the shared builder all three surfaces run through. A HEX counter collected at concurrency > 1 is detected again: arrival order is not issuance order, so correlation with it falls from 1.00 to ~0.02 and the row read "Sequential: none" for a textbook counter — the decimal path already re-checked the sorted values for an even step and hex, the encoding session ids are actually spelled in, did not. A finished manual paste reports `30/30`, not `30/500` — the terminal event carries no goal and the re-derivation read the live-replay one. Reconfiguring a session (`c`) keeps its samples / max requests / concurrency / notify instead of silently resetting all four to the card's defaults. Over MCP a sequence job now says WHY it has no tokens (`every replay failed — …`, the engine's reason, which nothing read: the raw samples are secrets and are never returned), reports `budget_exhausted` for a run that ended under its goal like fuzz/mine/discover already do, publishes `requests` — the real wire count its own 100k ceiling is enforced against — and takes `keep_alive`, the fresh-connection second reading `gori run sequence --no-keep-alive` has always had. A newline in a Markdown report cell no longer ends the row and the table under it, and `requests` now includes a keep-alive pool's stale re-sends — a whole request that leaves the machine inside one call, which `gori run fuzz` has always counted and the Sequencer, the run most exposed to it, did not
- CLI: `issues`, `issues create`, `issues update`, `repeater` and `repeater create` help now show how to attach flow/repeater/fuzz/miner evidence to an issue through `links add` (#1018)
- OAST: a registration that fails now names the STAGE it failed at instead of one shapeless sentence — an unresolved name, a refused port, a certificate chain this machine's trust store rejected, a handshake that never reached a certificate, a silent port, or the provider's own refusal are six different remedies, and gori says which one applies. `tls-verify` names `SSL_CERT_FILE` / `SSL_CERT_DIR` (for gori's own service traffic those are ADDITIVE to the system store, so a corporate-CA-only bundle does not stop the public presets from working); the other stages pointedly do not, since a CA bundle cannot fix a black-holed port. `gori run oast presets --check` probes every built-in provider at once and prints that stage per preset, which is what separates "this host is down, try a sibling" from "this machine rejects every public certificate", and a failed `oast listen` prints the next command that fits its stage (#1020)
- Issues: `gori run issues create` takes the notes body — `-n`/`--notes`, `--notes-file` or `--notes-stdin` — and writes it with the issue in ONE transaction, so a script no longer has to create an issue and then update it to give it a body (a peer reading between the two saw a titled finding with nothing in it). `update` gains the same `--notes-file`/`--notes-stdin` doors, so a long write-up need not go through the argument vector, where it sits in the process listing and the shell history. The three sources are mutually exclusive rather than resolved by flag order, and the body is read byte-for-byte — multiline UTF-8, CRLF and evidence that is not well-formed text all survive as themselves. A file or a pipe that yields NO bytes is refused rather than written: `--notes ''` is the one spelling that clears an issue's notes, so a report generator that dies mid-pipeline can no longer erase the write-up already on the issue and exit 0 saying "updated successfully". The TUI's issue form files its notes in the same one insert, so "created — but its notes did not save" is a half-landing that can no longer happen (#1019)
- Issues: the detail's RELATED card answers the pointer. A click puts the cursor on the link row under it (or jumps there from the card's scroll gauge), a double-click opens the linked flow / repeater / … in its own tab the way `↵` does, and a click anywhere else on the card just moves focus there — which is the only pointer affordance an issue with no links has. The wheel now scrolls the card under the cursor rather than whichever one holds the keyboard, a drag that starts on RELATED no longer extends a NOTES selection, and leaving the editor by clicking RELATED saves the writeup exactly as `esc` does, refusal included. A click into an open detail also takes body focus: with the tab bar focused it used to place the notes caret and then send the typing to the tab bar. And the shell frame stands down while a detail is open — both inner cards draw their own borders, so gilding the outline too read as "the whole tab is focused" and left the pane that actually owned the keyboard with nothing to distinguish it (#1021)
- JWT: signing and verification cover the asymmetric families a real OIDC deployment ships — **RS256/384/512**, **PS256/384/512**, **ES256/384/512** and **EdDSA** — with a PEM key you supply inline or by path (`--key`, MCP `key`); gori generates none, so forging an `RS256` token still needs the `RS256` private key. `gori run jwt --verify` and MCP `jwt_verify` answer "would a server holding this key accept this token", verifying under the alg the TOKEN declares, and take a public key, a certificate, or the private key. Given the server's public key, `--attacks` adds the **algorithm-confusion** family: `HS256` re-signs keyed with the public key's own bytes, one per spelling a server might hold. An encrypted five-part **JWE** is now recognized everywhere a JWS is and shows its protected header (`alg`/`enc`/`kid`) instead of rendering as an opaque dotted string; gori does not decrypt, so the claims are marked encrypted, no attack payloads are generated from one, and a passive scan no longer reports every encrypted token as "signed with a non-standard algorithm" (#1010, #1015)
- Decoder: gori now READS the native-serialization blobs it already flagged — `java-deserialize`, `dotnet-viewstate`, `php-unserialize` and `pickle-disasm` render a Java stream, an ASP.NET ViewState, a PHP `serialize()` value or a Python pickle as a labelled JSON tree, in the Decoder tab and, for a body carrying one of their markers, in the detail pane. A pickle is disassembled and never executed, a ViewState says whether it carries a MAC, a Java or PHP back-reference comes back as `{"$ref": n}` rather than expanded, and reading is all they do — gadget-chain generation stays an out-of-tool `ysoserial` step (#1011)
- WebSocket: the framings that ride inside a socket are decoded, not just GraphQL-over-WS — **Socket.IO / Engine.IO**, **SignalR**, **STOMP**, **SockJS** and **Action Cable** get a detail pane named after the framing, plus a `ws_proto` key in `gori run show --format json` and MCP `get_flow`, with the event name / hub method / destination / channel lifted out of the envelope an operator was reading by eye. A protocol is offered only once the transcript carries a frame that could be nothing else, so a `2` heartbeat or a lone `h` never claims a socket; `Sec-WebSocket-Protocol` is a hint that can open a decoder for an all-heartbeat session, never an authority over what a frame is. SockJS wraps another framing, so its messages are unwrapped and re-decoded (`stomp via sockjs`) and the pane names what is carried rather than the shim. Raw frames stay the truth in MESSAGES; a frame that does not parse falls through to raw, never to a guess (#1009)
- Discover: a brute-force hit's body is read for endpoints, so finding `swagger.json`, an autoindex page or a config file starts a crawl instead of producing a single row. Only hits are read — the thousands of soft-404s a sweep sends still cost nothing
- Discover: links a response declares in its HEADERS are followed — `Link` (RFC 8288, how a paginated API names its next page and nowhere else), `Content-Location`, `Refresh`, and the subtree a `Set-Cookie` scopes itself to with `Path=`
- Discover: the API-description documents (`openapi.json`, `swagger/v1/swagger.json`, `v3/api-docs`, `v2/api-docs`) and the root `apple-app-site-association` join the well-known set fetched once at the origin, and the whole set is registered as visited so the origin's own directory sweep no longer re-requests each of them
- Discover: a `405` is recorded as proof a path exists. A form target, a JSON API that only takes `POST` and a WebDAV collection each answer `GET` once with `405`, and were dropped
- Discover: linked images, fonts, media and archives are no longer downloaded — a request and a full body each, for bytes no extractor can read, which also spent the crawl's page budget. Their directory is still swept (`/uploads/` because `/uploads/photo.jpg` was linked) and the count is reported as `assets`; `--assets` / `crawl_assets` / the **fetch images/fonts/media** checkbox restores the fetch
- Discover: an html body is scanned into text once for its links and its `<base href>` instead of once each (10% off per-page extraction, 1 MB/response less allocated on a large page), and `--extensions php` no longer probes `admin.php.php` for every already-dotted word in the list
- History: `body~`, `header:` and index-free `body:` no longer run the regex engine over every stored byte. A literal needle is answered by a byte search instead, allocating nothing (`body~` across 500k flows: 4.1s → 0.25s, 688MB → ~1KB; `header:` 199ms → 120ms), and a real regex stops paying to validate each body twice (2-4x, whether the capture holds text or compressed bytes). A `body:`/`header:` needle under three characters also folds case the same way a longer one does now, so it can no longer match fewer rows than the longer needle containing it.
- OAST: `gori run oast listen --save` and MCP `oast_start{persist:true}` keep the registration as a project session, so a headless or agent-driven listener lands in `oast list` / `list_oast_sessions`, is re-openable with `resume`, and — the reason it matters — gives the blind `ssrf_oast` / `xxe_oast` / `cmd_injection_oast` rules a session to mint payloads against. Only the TUI could write one before, so those rules ran inert everywhere else
- MCP: `probe_scan{active:true}` reports an `out_of_band` block when an enabled out-of-band rule had no OAST session to plant against, instead of returning an empty `issues` array that reads as "no blind vulnerability" — the notice `gori run probe` already printed
- OAST: a listener that has stopped REACHING its provider (a rotated api key, an expired webhook token) draws "not answering" instead of a green ●listening and raises a notification, rather than looking busy while every planted payload calls home to nobody
- OAST: webhook.site, BOAST and postbin gave an interaction whose item carried no server-side id a RANDOM dedup key, so on the two providers that re-serve their whole buffer each poll it was re-announced and re-recorded every cycle; the fallback is now a content hash, as interactsh and custom-http already used. postbin's callback destination shows the path that was hit rather than repeating its request id
- Docs: two Reference pages for the artwork — **Brand Kit** (the three logo variants, the brand palette with where each value lives in the TUI and on the site, and the wallpapers, all downloadable) and **Miss Ring** (the character she was drawn from, the 8x3 half-block grid, and every pose and badge). The header's logo menu now links to the kit.

- Docs: an accuracy pass over the English and Korean guides — corrected keys (deleting marked flows, Sitemap tagging), the rule host-scope and colour-rule condition semantics, per-field `Alt-Svc` stripping, undocumented `gori run` flags and MCP tool gating, and restored dropped Korean paragraphs.
- TUI/CLI/MCP: every place gori names the scope-lens key now says `s` — the two `--in-scope` help lines, the History and Probe empty-state hints, the colour-rule advice note and the MCP scope arguments still named `⇧S`, the twin key removed when the lens became the Global `s` (#959)
- Issues: CVSS v2.0 vectors written in the parenthesised form NVD's v2 calculator renders — `(AV:N/AC:L/Au:N/C:P/I:P/A:P)` — are accepted and scored instead of refused (cvss.cr 0.3.0, #994)
- Repeater: `gori run repeater create --request-stdin` reads the raw request from a pipe, byte-for-byte as `--request-file` reads a file, so a generated or large request need not go through the argument vector — where it sits in the process listing and counts against the command-line length limit. The three request sources are now mutually exclusive rather than resolved by flag order (`--request-file f --request-raw '…'` used to store the file and never mention the string), and a request that arrives empty from any of them is refused instead of creating a session that cannot be sent. Both it and every other stdin road a flag names — `--notes-stdin`, and the four that spell stdin `-` — read a pipe or a redirect and refuse a terminal, which would echo the request (`Cookie` and `Authorization` with it) into the scrollback and any captured PTY transcript, and whose `^D` flushes a partial line instead of ending the read (#1001, #1034)
- History: `gori run history --format json` redacts `Authorization`/`Cookie`/`Set-Cookie`/`Proxy-Authorization`/API-key header VALUES — in each row's `headers` object and in a `header:`/`cookie:` column, the latter drawn by default from the project's configured set — and marks the row `sensitive_headers_redacted`. A listing is an inventory, and one run put live session material into terminal logs and agent transcripts; `--include-sensitive` returns the exact bytes, as it already did on `gori run intercept`. An obs-fold continuation of a sensitive header no longer surfaces as a header of its own with its value in the clear; it is folded into the field it continues (#1002)
- Miner: building a JSON probe no longer scans the whole body once per candidate name to locate the injected spans — a nested body was spending ~80x the reserialization itself there (a 256-name bucket over a 32-node body: ~117ms → ~1ms per probe). The injected canary values are unique, so one scan of the body finds them all; the output bytes are unchanged
- Issues: the detail's RELATED list is a bordered pane of its own, so focus moving between it and NOTES is visible — on an issue with no links it changed nothing on screen at all. `↓` past the last related row enters NOTES; `↑` comes back from its first drawn row (the pane soft-wraps, so that is a visual row, not a logical line) and `←` from the very start of the notes, where neither key had anywhere else to go; `↹` walks the two panes instead of handing focus to the tab bar and leaving the detail drawn with every key dead, which Probe's detail did too
- Issues, Probe: the `/` filter bar completes the way History's does — a row naming what `↹` takes and what it means, `↓` for the full list, values for `severity:`, `status:`, `category:`, `host:` and `code:`, and `?` for a reference written for these two backends rather than QL's. A negated or grouped field (`-sev`) completes at all now, and a word-delete on the bar re-derives the list instead of leaving it stale. Probe's reference no longer offers `title:`, a field that backend has never had, and a caret move on either bar (Home/End/⌥←/⌥→) stops re-running the filter over every row
- MCP: the handshake `instructions` no longer call the project a pin. That sentence is sent once and cached by the client for the whole session, so after `switch_project` it went on naming the project the server started on while every call read and wrote the new one — a split an agent recording evidence has no reason to distrust. It now says the binding describes the handshake only, names `project_info` as the live answer, and reports the project in force at the moment it is built (a client that re-handshakes gets the current one). `switch_project`, and `create_project` when it auto-binds, return that correction plus the `previous_project` they moved off — the db path when the binding was an unnamed `--db` file (#1003)
- Probe: the detail's AFFECTED URLS list is a bordered pane of its own, the shape Issues' RELATED list was just given, with the count and the `seen ×N` total in the card's right-aligned border slot instead of a heading whose width moved with the number. It costs no rows — the heading rides the top border — and it is the region focus lives in, so the outline dims when the body loses focus. The list's geometry now has one derivation the renderer and both pointer hit-tests read; they each did the arithmetic separately, and any future row added above would have put every click on the wrong URL with nothing to catch it. A finding whose stored URL list will not parse says so instead of showing an empty pane
- Probe: a finding's remediation text is its own DESCRIPTION pane under the affected URLs, instead of one row of the header that ended nearly every rule's sentence in `…`. It takes focus — `⇥` between the two panes, or `↓` off the last affected URL and `↑` back — so the text can be scrolled, selected with ⇧arrows and copied with `y` or the space menu, all of which a plain header row could never offer; it takes no edit. The detail's read verbs follow whichever pane holds focus, and `↵` opens a URL only from the URL list rather than firing over a paragraph of prose. `↓` off the last affected URL also works when that URL wraps, where it used to do nothing at all
