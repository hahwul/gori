**Agent** 탭은 운영자 자신의 코딩 에이전트 — 우선은 Claude Code — 를 gori의 자식 프로세스로 호스팅하고, 그 대화를 탭 안에 그대로 보여줍니다. gori는 스스로 모델을 호출하지 않습니다. [#98](https://github.com/hahwul/gori/issues/98) 무렵에 기록된 결정 — 내장 AI 챗은 만들지 않는다 — 은 그대로 유지되며, 이 탭도 그 결정을 바꾸지 않습니다. 이 탭이 호스팅하는 것은 여러분이 이미 컴퓨터에서 쓰고 있는 에이전트, 즉 쉘에서 직접 입력했을 그 `claude`이며, 첫 턴이 시작되기 전에 이 프로젝트 자신의 MCP 도구가 쥐여집니다. 그래서 아무것도 붙여넣지 않아도 History, Sitemap, Repeater 탭, Issues를 읽을 수 있습니다.

## 이것이 아닌 것

- `gori mcp` 옆에 사는 또 하나의 AI 기능이 아닙니다 — 오히려 `gori mcp`를 *구동*합니다. gori가 써 준 설정 파일을 통해, 외부 에이전트가 접속할 때와 같은 그 서버로요.
- gori는 모델로 무언가를 결정하지 않습니다. 에이전트가 하는 모든 변경 동작은 자식 프로세스가 거는 도구 호출이며, 그 하나하나는 여전히 gori 자신의 도구 표면을 거치고, 아웃바운드 트래픽이라면 [Outbound](/guide/proxy/#scope) 스코프와 샌드박스도 거칩니다.
- 타깃에 대해 한 번 질문을 던지고 허공에서 합성된 답을 받는 자리가 아닙니다 — 에이전트의 맥락은 다른 모든 MCP 클라이언트와 똑같이 MCP를 통해 여러분의 프로젝트에서 옵니다.

## 요구 사항

- `PATH`에 있는 `claude` 바이너리 — 여러 빌드를 두고 쓰는 경우라면 `agent.command`에 경로를 지정하세요.
- 이미 로그인된 Claude Code. gori는 이를 실행할 뿐 인증하지 않습니다.

바이너리가 없으면 탭 본문은 빈 트랜스크립트 대신 설치 안내를 보여줍니다. 조용히 실패하지 않습니다.

## 탭 구성

위에서 아래로 세 부분입니다.

- **트랜스크립트 패널.** 지금까지의 대화입니다. 도구 호출과 그 결과는 기본적으로 한 줄씩 접힙니다 — `▸ Bash(git status)` 다음 `  ✓ 12 lines` — 그래서 긴 `ls` 출력이나 가져온 응답 바디가 그 앞뒤 두 문장을 묻어 버리지 않습니다. `↵` 또는 클릭으로 커서 아래 호출을 펼쳐 입력과 출력을 보여주고, 같은 키로 다시 접습니다.
- **상태 밴드.** 한 줄입니다. 턴 사이에는 `idle · <model> · 3 turns · $0.14`, 에이전트가 작업 중이면 `running ⟳`, 도구 호출이 답을 기다리면 `⚠ 2 permission requests`, 자식 프로세스가 사라지면 `dead: <reason>`.
- **입력 패널.** 여러 줄이며, Notes와 같은 insert/read 구분을 씁니다. `i`로 insert 모드에 들어가고, `esc`로 read 모드로 돌아오며, read 모드에서 `↵`가 전송입니다(`^S`도 같은 동작이라, 전송하려고 insert 모드를 나올 필요가 없습니다).

| 키 | 동작 |
|-----|--------|
| `i` | Insert 모드 |
| `esc` | Read 모드 |
| `↵` (read 모드) / `^S` | 전송 (`agent.send`) |
| `^X` / `agent.interrupt` | 실행 중인 턴 취소 |
| `agent.history` | 이 프로젝트의 과거 대화 피커 열기 (읽기 전용 뷰) |
| `agent.restart` | 마지막 대화 재개 (`--resume`) |
| `agent.new` | 새 대화 시작 |
| `agent.fold` | 커서 아래 도구 호출 접기/펼치기 |
| `agent.copy` | 선택 영역 복사, 선택이 없으면 트랜스크립트 전체 복사 |

## 다른 탭에서 물어보기

`agent.ask`는 Global 버브입니다 — Agent 탭이 아니라 어느 탭에서나 동작합니다 — 커맨드 팔레트에서 **"Ask the agent"**로 찾을 수 있습니다. 한 줄짜리 프롬프트를 열어 입력한 내용을 턴으로 보내고, 하던 작업으로 돌려보내 줍니다. Agent 탭으로 굳이 넘어갈 필요가 없습니다. 답이 도착하면, 다른 백그라운드 결과와 마찬가지로 바로 가기 링크가 있는 알림으로 옵니다.

## 권한

CLI라면 스스로 물어봤을 도구를 에이전트가 실행하려 하면, gori는 자식이 알아서 결정하게 두는 대신 세 가지 답을 가진 카드를 띄웁니다.

| 키 | 답 |
|-----|--------|
| `a` | Allow |
| `d` / `esc` | Deny |
| `s` | Allow for this session |

"Allow for this session"은 이 호스팅된 대화 하나가 살아 있는 동안만 gori가 메모리에 쥐고 있는 허가입니다 — 운영자의 `~/.claude/settings.json`에는 쓰이지 않으며, CLI 자체의 "규칙 추가" 제안도 전혀 제공되지 않습니다. gori는 gori 안에서 일어나는 일만 바꿉니다. 여러분의 Claude Code 설정을 몰래 고치지 않습니다.

카드가 뜰 때 다른 탭에 있었다면, 알림(`source: agent`)이 Agent 탭을 가리키고, 요청은 큐에 그대로 남습니다 — CLI는 그 도구 호출과 그 뒤의 턴 전체를 누군가 Agent 탭에서 답할 때까지 붙들고 있습니다.

분명히 해 둘 두 가지입니다.

- **여러분의 Claude Code 설정이 이미 허용 목록에 올려둔 도구는 애초에 프롬프트를 만들지 않습니다.** gori는 CLI가 실제로 물어본 것만 게이트할 수 있습니다. 이미 자신의 설정에서 신뢰한 규칙은 이 카드에 닿지도 않고 실행됩니다.
- **묻지 않는 권한 모드도 마찬가지입니다.** 자신의 Claude Code 설정에서 `permissions.defaultMode`가 `auto`나 `bypassPermissions`이면 CLI가 모든 도구 호출을 스스로 결정하고 카드는 뜨지 않습니다. gori가 묻게 하려면 `agent.args`에 `--permission-mode default`를 넣으세요.
- **`agent.permission_policy = "deny"`는 모든 것을 자동으로 거부합니다.** 자동으로 *허용*하는 정책 값은 일부러 두지 않았습니다 — 선택지는 "나에게 물어봐라"거나 "전부 거절해라"뿐이며, "뭐든 알아서 실행해라"는 없습니다.

## 히스토리와 재개

대화는 프로젝트 데이터베이스(`agent_sessions`, `agent_messages`)에 저장됩니다 — 캡처된 트래픽과 같은 데이터베이스라서, 이 인게이지먼트에 대한 에이전트 대화가 함께 따라다닙니다. 스트리밍되는 델타는 절대 저장되지 않고, 완성된 메시지만 온전한 상태로 저장됩니다.

`agent.history`는 과거 대화를 읽기 전용으로 엽니다. `esc`로 라이브 대화로 돌아옵니다. `agent.restart`(`⇧R`)는 자식이 종료된 뒤 라이브 대화의 CLI 맥락을 `--resume`으로 재개합니다. gori 쪽 트랜스크립트만 이어지는 게 아니라 모델도 멈춘 지점에서 다시 시작합니다. CLI 자신의 세션 상태가 나중에 지워지더라도 gori의 사본은 남습니다 — 둘은 관련되어 있지만, 저장된 행이 CLI 파일의 캐시는 아닙니다.

`agent.history_keep`(기본값 50)이 프로젝트당 보관할 과거 대화 수의 상한입니다. 그 수를 넘으면 가장 오래된 것부터 정리됩니다.

## 설정

`settings.json`의 `agent` 섹션입니다 (Preferences → 설정 피커, 또는 파일을 직접 편집).

| 키 | 기본값 | 의미 |
|-----|---------|---------|
| `command` | `"claude"` | 실행할 바이너리 — `PATH`로 찾을 이름, 또는 절대 경로 |
| `args` | `""` | gori가 만든 것 뒤에 덧붙는 추가 argv. 쉘 한 줄 텍스트처럼 토큰화됩니다(쉘이 아니므로 `$`, `;`, `` ` ``, `\|`는 그대로 문자) |
| `model` | `""` | 설정되면 `--model`로 전달됩니다. 비어 있으면 CLI 자신의 기본값 |
| `mcp_read_only` | `false` | 에이전트의 `gori` MCP 서버를 `--read-only`로 띄웁니다. 프로젝트를 읽을 수는 있지만, 변경하는 도구는 프롬프트로 걸러지는 게 아니라 서버 단에서 아예 거부됩니다 |
| `system_prompt_append` | `""` | gori 자신의 안내 프리앰블 뒤에 덧붙습니다. 대체하지 않습니다 |
| `permission_policy` | `"ask"` | `"ask"`는 권한 카드를 띄우고, `"deny"`는 CLI가 물어봤을 모든 도구를 자동으로 거부합니다 |
| `history_keep` | `50` | 가장 오래된 대화가 정리되기 전까지 프로젝트당 보관할 대화 수 |

모든 키와 정확한 동작: [설정 레퍼런스의 `agent`](/reference/config/#agent).

한 번 짚어 둘 만한 것은 `mcp_read_only`입니다. 기본값은 전체 액션입니다. 여기서 띄운 에이전트는 첫 턴부터 이 프로젝트에서 요청을 보내고, 퍼징하고, 마이닝하고, 이슈를 파일링할 수 있습니다. 여러분이 직접 MCP로 명령을 친 것과 똑같이요 — 건드리지 않고 들여다보기만 하길 원한다면 `mcp_read_only`를 켜세요.

## Miss Ring

Companion이 켜져 있으면(다른 모든 companion 동작처럼 기본은 꺼짐) [Miss Ring](/guide/settings/#appearance)이 호스팅된 에이전트에 반응합니다. 다른 탭을 보는 동안 권한 요청이 도착하면 경고 표정과 말풍선을, 다른 탭에 있는 동안 턴이 끝나면 답변 첫 줄과 함께 기쁜 표정을, 자식 프로세스가 죽으면 오류 표정을 보여줍니다.

## 종료 시 자식 프로세스는 어떻게 되는가

gori를 종료하거나 프로젝트를 떠나면 에이전트의 stdin을 닫습니다 — `stream-json` 세션의 정상 종료 방법이죠 — 그런 다음 잠깐 기다리고, `SIGTERM`을 보내고, 다시 기다리고, 그래도 남아 있으면 마지막으로 `SIGKILL`합니다.

이 단계는 `claude` 프로세스 자체에는 닿습니다. 하지만 Crystal의 `Process`에는 `setpgid`가 없어서, 에이전트가 스스로 띄운 것 — 예를 들어 `Bash` 도구 호출 안의 `sleep` — 은 gori가 시그널을 보낼 수 있는 프로세스 그룹에 들어 있지 않고, gori 자신의 종료보다 오래 살아남을 수 있습니다. 이런 것들을 정리하는 몫은 에이전트 자신의 시그널 처리에 있습니다. gori를 (위의 순차적 단계 대신) `SIGKILL`로 죽이면 그 처리 자체를 건너뛰게 되어, 에이전트뿐 아니라 그 아래 트리 전체가 고아가 됩니다.

## 한계

- **v1은 Claude Code뿐입니다.** 백엔드 seam은 나중에 다른 ACP 계열 에이전트를 받아들이도록 짜여 있지만, 아직 그 외에는 아무것도 연결되어 있지 않습니다.
- **권한 프롬프트의 와이어 프로토콜은 Anthropic 쪽에 문서화되어 있지 않습니다.** gori 쪽 구현은 Claude Code 자신의 동작을 관찰해서 읽어낸 것이고, CLI가 필요한 능력(`interrupt_receipt_v1` 등)을 광고하는지에 걸려 있습니다 — gori가 의존하는 능력을 광고하지 않는 빌드는 탭 전체가 아니라 그 기능 하나만 저하됩니다.
