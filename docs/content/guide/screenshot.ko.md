스크린샷은 실제 껍데기 — 목업이 아니라 출시되는 그대로의 UI — 를 파일로 씁니다. 백엔드가 마지막으로 화면에 올린 바로 그 프레임을, 메뉴는 모두 닫은 채로, 프로젝트의 리댁션 프로파일을 위에 칠한 뒤에요. JSON 내보내기가 줄 수 없는 것 두 가지가 이 기능의 자리를 만듭니다. 그림은 **증거**입니다 — 어떤 결함을 입증한 바로 그 레이아웃을, 리포트나 이슈에 그대로 붙여 넣을 수 있습니다. 그리고 그림은 **에이전트**가 실제로 필요로 하는 것이기도 합니다. "이 패널이 어떻게 생겼나"라는 질문에는 "무슨 행을 갖고 있나"가 아니라 그림으로 답해야 할 때가 있습니다 — 차트, 배지, 줄바꿈된 컬럼처럼 JSON 도구가 말하지 못하는 모양을요.

세 표면 모두 같은 이음매를 지나갑니다. `Tui::Headless.render`가 `gori`를 띄울 때와 같은 Runner를 띄우므로, 버그 리포트에도 README에도 에이전트의 대화 기록에도 붙는 그림은 언제나 실제로 나간 버전입니다. 겉모습만 흉내 낸 목업이 끼어들 자리가 없습니다.

## TUI에서

커맨드 팔레트(`Ctrl-P`) 항목 둘:

| Verb | 팔레트 이름 | 하는 일 |
|------|------------|--------|
| `screenshot` | **Screenshot** | 지금 화면을 바로 파일로 씁니다 — 형식과 디렉터리는 [`settings:screenshot`](#settings)에서 옵니다 |
| `screenshot.save-as` | **Screenshot to…** | 설정 기본값이 미리 채워진 내보내기 카드를 엽니다. 입력한 확장자(`.svg`, `.png`, `.ansi`, `.txt`)가 형식을 정합니다 |

둘 다 스페이스 메뉴(`Space`)와 Help에도 나타납니다. 어느 쪽에도 기본 단축키는 없습니다. Global 전용 한 글자 예산은 이미 `c`/`i`/`s`로 다 썼고, 진행 중인 점검의 그림은 무심코 누른 키가 아니라 팔레트를 거치는 의도적인 행동이어야 하기 때문입니다.

찍히는 것은 **지금 있는 그대로의 화면**이되, 한 가지는 손을 봅니다. 팔레트와 스페이스 메뉴는 먼저 스스로 닫히므로, 그 verb에 닿으려고 열었던 메뉴 자체가 찍히는 일은 없습니다. 그 밖의 모든 것 — 열려 있는 상세 패널, 스크롤해 둔 목록, 띄워 둔 카드 — 은 **그대로 찍힙니다**. 대체로 그게 정말 찍고 싶었던 것이기 때문입니다.

쓰고 나면 토스트가 무슨 일이 있었고 어디로 갔는지 말해 줍니다:

```text
screenshot written · SANITIZED (3) · /Users/you/.gori/screenshots/acme-history-20260918-141205.svg
```

`SANITIZED (N)`은 리댁션 프로파일이 실제로 돌았고 무언가를 가렸을 때만 나타납니다. 아래 [리댁션](#redaction)을 보세요.

### 설정 {#settings}

Preferences(`Ctrl-,`) → **Appearance** → **Screenshot**, 또는 팔레트의 **`settings:screenshot`**:

| 필드 | 기본값 | 의미 |
|------|--------|------|
| Format | `svg` | **Screenshot**이 쓰는 형식: `svg`, `png`, `ansi`, `txt` 중 하나 |
| Directory | *(빈 값)* | 저장 위치. 비워 두면 `~/.gori/screenshots/` |
| PNG scale | `2` | 터미널 한 칸의 변마다 들어가는 픽셀 수, `1`–`8`. `png`에서만 읽습니다 |

기본 파일명은 `<프로젝트>-<탭>-<YYYYmmdd-HHMMSS>.<형식>`이고, 같은 이름이 이미 있으면 `-2`, `-3`… 접미사가 붙습니다 — 1초 안에 몰아 찍어도 서로 덮어쓰지 않습니다. 필드 전체 레퍼런스: [설정 레퍼런스의 `screenshot`](/ko/reference/config/#screenshot).

## 헤드리스, 셸에서

`gori run screenshot`(별칭 `shot`)은 터미널을 붙이지 않고 같은 TUI를 그려 오프스크린 터미널(기본 132×38 — gori 자신의 문서가 찍히는 크기이며, `--size WxH`로 바꿀 수 있습니다) 위에 띄운 뒤 프레임을 파일로 씁니다. 프로젝트는 **읽기 전용**으로 열립니다: 포트를 잡지 않고, 캡처 잠금도 가져가지 않으며, 활성 프로젝트 포인터도 건드리지 않습니다.

```bash
# 현재 프로젝트 홈 탭의 SVG, 기본 크기
gori run screenshot

# 탭으로 이동한 뒤 그리기
gori run screenshot --tab history -o history.svg

# tmux send-keys 문법으로 먼저 이동한 뒤 그리기
gori run screenshot --tab repeater --keys 'Down Down Enter' -o repeater.svg

# 특정 테마로 — 문서 그림을 페이지와 맞출 때
gori run screenshot --theme goriday --tab issues -o issues-light.svg

# 비트맵만 받는 곳을 위한 레티나급 PNG
gori run screenshot --format png --scale 2 -o docs/shot.png

# 다른 터미널에서 돌고 있는(또는 이미 끝난) gori
tmux capture-pane -e -p -t gori | gori run screenshot --from-ansi - -o remote.svg
```

`--keys`는 **이동**을 시킬 뿐, 기다려 주지 않습니다. 프레임은 저장소가 **바로 지금** 어떤 상태인지를 찍은 그림이므로, 키 스크립트로 시작한 Repeater 전송이나 스캔은 끝나기를 기다리지 않고 진행 중인 모습 그대로 찍힙니다. 이미 데이터베이스에 있는 것 — 탭, 필터, 선택 — 을 향하게 하세요. 방금 트리거한 비동기 작업이 아니라요.

전체 플래그 표와 모든 거절 사유, `--from-ansi` 수집 규칙: [CLI 레퍼런스의 `run screenshot`](/ko/reference/cli/#run-screenshot).

## 에이전트에서

MCP `screenshot` 도구는 같은 방식으로 바인딩된 프로젝트를 그립니다 — 실제 껍데기, 읽기 전용, 캡처 칩은 `off` — 그리고 쓴 경로를 돌려줍니다. `inline:true`를 주면 도구 결과 안에 그림도 함께 받습니다. PNG는 `image/png` content 블록으로, SVG/ANSI/TXT는 문서 자체가 텍스트 블록으로 옵니다. 인코딩 기준 1 MiB를 넘으면 거절되므로, 큰 그림이 필요한 에이전트는 한도를 올리는 대신 `cols`/`rows`로 그림을 좁혀야 합니다.

```json
{
  "tab": "issues",
  "keys": "C-p \"acme\" Enter",
  "format": "png",
  "inline": true
}
```

이 도구는 프로젝트 데이터베이스 바깥에 파일을 쓰는, 다른 읽기 도구는 하지 않는 유일한 일을 하므로 **게이트된 쓰기 도구**입니다. 하지만 agent action은 아닙니다. 프로젝트 안에서 바뀌는 것이 없고, 밖으로 나가는 것도 없으며, 스크린샷마다 이벤트 피드에 행 하나가 남으면 그 피드가 정말 보여주려는 변경들이 묻혀 버립니다. `--read-only` 아래서는 쓸 수 없습니다. 나머지 도구 목록은 [MCP 도구](/ko/guide/mcp/#tools)를, `cols`/`rows`/`theme`/`scale`/`overwrite`/`include_sensitive` 같은 필드는 도구 자신의 필드 목록을 보세요.

## 리댁션 {#redaction}

진행 중인 점검의 스크린샷은 증거이고, 쓰이는 순간 gori 프로세스를 떠납니다. 그래서 프레임 파일에 바이트 한 개가 닿기도 전에 프로젝트의 리댁션 프로파일이 프레임의 **셀** 위에 칠해집니다. 내보내기의 `--redact`나 복사 메뉴가 본문에 이미 적용하는 것과 같은 [리댁션 프로파일](/ko/reference/cli/#run-redact)입니다. CLI의 `--redact`/`--no-redact`와 MCP의 `include_sensitive`가 두 가지 우회 스위치이고, TUI의 verb 둘은 언제나 프로젝트의 앰비언트 프로파일을 따릅니다.

솔직하게 그 모양을 말하면:

- **가려지는 것.** 패널이 실제로 그린 텍스트 위에서, 본문 모양의 비밀값들입니다: 프로파일이 지정한 필드 이름이 `"name": "value"`나 `name=value`로 다시 나타난 것, 프로파일 자신의 패턴, 그리고 gori가 언제나 찾는 내장 자격증명 모양 두 가지 — JWS compact 직렬화(JWT)와 PEM 개인키 블록입니다. 화면 두 줄에 걸쳐 접힌 비밀값은 매칭하기 전에 다시 이어 붙이므로, 좁은 패널에서 중간에 줄바꿈된 긴 토큰도 통째로 잡힙니다.
- **가려지지 않는 것.** 헤더는 gori 어디서나 모든 프로파일의 범위 밖입니다 — 복사 메뉴도 헤더는 건드리지 않습니다 — 그래서 화면에 `token=…`처럼 보이는 헤더는 다른 텍스트와 마찬가지로 폼 키 규칙에 걸리지만, 프로파일이 따로 지목하지 않은 헤더 값은 걸리지 않습니다. 컬럼 폭 때문에 잘린 값(`sec…`)은 패턴이 알아볼 최소 길이 아래로 떨어질 수 있습니다. 그리고 hex 뷰는 텍스트가 아니라 바이트를 그리므로, `"password"`를 찾는 매처는 hex 쌍이 늘어선 페이지를 보지 못합니다.
- **개수도, 그 부재도 정직합니다.** 태그를 넣기에 충분히 넓은 영역은 리댁션된 내보내기와 같은 `[REDACTED:…]` 상관관계 태그를 답니다 — 같은 값을 담은 스크린샷 두 장은 같은 태그를 갖습니다. 너무 좁은 영역은 `▒`로 채워집니다. 태그의 절반만 보이면 잘린 비밀값처럼 읽히기 때문입니다. 토스트의 `SANITIZED (N)`은 프로파일이 실제로 돌았을 때만 나타납니다. 프로파일이 설정돼 있지 않으면 어느 쪽으로도 주장하지 않으며, 이는 "돌았지만 아무것도 못 찾음"(`SANITIZED (0)`)과는 다른 이야기입니다.

리댁션은 **그림**만 바꾸지 저장소는 바꾸지 않습니다 — 캡처된 바이트는 그대로 있고, 같은 살아 있는 세션을 프로파일 켜기 전후로 찍은 두 스크린샷은 서로 다르게 보이지만 History는 여전히 같은 행을 갖고 있습니다.

## 형식과 폰트

| 형식 | 무엇인가 | 이럴 때 |
|------|---------|---------|
| `svg` (기본) | 자체 완결형 벡터: 창 크롬, `textLength`로 정렬된 그리드, `data-theme`/`-cols`/`-rows`/`-sanitized` 속성. 텍스트가 선택되고 검색됩니다. 크기는 수십 KB 정도 | 또렷하고 작은 기본값을 원할 때 — gori 자신의 문서도 이걸로 찍습니다 |
| `png` | 내장 비트맵 폰트로 렌더링한 래스터 이미지 | 비트맵만 받는 곳: 채팅, 이슈 트래커의 붙여넣기 상자, 이미지를 읽는 에이전트 |
| `ansi` | 트루컬러 SGR 이스케이프, CRLF 줄바꿈 | 터미널에 다시 붙여 넣거나 `--from-ansi`로 나중에 다시 읽어 들이고 싶을 때 |
| `txt` | 색 없는 평문 글리프, 크롬 없음 | grep, diff, 그 외 모든 것을 벗겨내야 하는 곳 |

**PNG와 내장 폰트.** gori는 GNU Unifont 18.0.01(SIL OFL 1.1)의 부분집합을 바이너리에 그대로 구워 넣습니다 — 라틴, 그리스, 키릴, 기호, 상자 그리기, 점자, 가나, 한글 음절 전체까지 — 그래서 PNG를 그리는 데 시스템 폰트도 폰트 서버도 필요 없습니다. CJK 한자와 이모지는 의도적으로 빠져 있습니다(Unifont의 대부분을 차지하고, 터미널 스크린샷에서 필요한 경우가 드뭅니다). gori가 글리프를 갖고 있지 않은 코드포인트는 조용히 빈칸으로 남지 않고 **두부(tofu)**, 속이 빈 네모로 그려집니다. 그래도 그려야 한다면 완전한 Unifont `.hex`를 `~/.gori/fonts/unifont.hex`에 두거나, `$GORI_SCREENSHOT_FONT`로 경로를 가리키거나, 시스템 `unifont` 패키지를 설치하세요 — 흔한 Homebrew 경로는 gori가 자동으로 찾아봅니다. 외부 파일은 내장 부분집합 위에 병합됩니다 — 외부 글리프가 이깁니다.

**안티앨리어싱.** `--scale`은 리샘플링이 아니라 블록 복제입니다 — 각 셀을 한 번 그린 뒤 그대로 `scale`번 반복하므로, 배율을 올려도 글리프 가장자리는 부드러워지지 않고 그대로 각져 있습니다. 부드러운 비트맵이 필요하면 SVG를 그린 뒤 변환하세요:

```bash
gori run screenshot -o shot.svg
rsvg-convert shot.svg -o shot.png
```

## 헤드리스 샷은 어떻게 보이나

`gori run screenshot`이나 MCP 샷은 아무것도 캡처하지 않았고, 그 사실을 숨기지 않습니다. 상단 바의 캡처 칩은 `off`로 보입니다. 이 프로세스가 포트를 잡지도 캡처 잠금을 가져가지도 않았기 때문이고, 실제로 캡처 중인 인스턴스가 있다면 그쪽은 손대지 않은 채로 남습니다. 그 밖의 크롬은 실제로 붙어 있는 세션과 똑같이 그려집니다. 시계도 마찬가지입니다. 렌더링하는 순간의 `Time.local`이지 멈춰 있거나 가짜로 만든 시각이 아니므로, 같은 프로젝트를 아무것도 바꾸지 않고 1분 간격으로 두 번 찍어도 시계는 서로 다르게 나옵니다.
